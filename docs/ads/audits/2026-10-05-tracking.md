## Appendix B. Platform setup rules

**Google Ads (google-search-v1)**
1. Goals → Conversions → New → Website → **"Set up manually using code"** (not "URL", not "Import from GA4"). Category: Submit lead form. Value: don't use a value (v1). **Count: One.** Click-through window: 90 days. Enhanced conversions: on, method "Google tag", via code (the site sets `user_data` at `track.ts:51`).
2. Copy the full `send_to` (`AW-…/…`) into `NEXT_PUBLIC_GOOGLE_ADS_LEAD_LABEL`, and the `AW-…` part into `NEXT_PUBLIC_GOOGLE_ADS_ID`. Redeploy.
3. Make this action the **only primary** conversion for the campaign's goal.
4. **Never** create a URL-based ("page load") conversion on `/scope-received`. It would double-count with the event and count refreshes.
5. If GA4 is linked, import `generate_lead` as **secondary** only. Never primary.
6. Auto-tagging **on** (Account settings), so `gclid` reaches the URL and the lead email.
7. GA4: mark `generate_lead` as a key event. Do **not** mark `scope_partial_captured`, `scope_form_started`, `scope_cta_clicked`, `email_click`, `phone_click` or any other `track()` event (see N12).

**Meta (meta-retargeting-v1)**
1. Business Manager → Brand safety → Domains → verify `skoxsoftware.com` (DNS TXT on Vercel).
2. Events Manager → the pixel → Aggregated Event Measurement: **`Lead`** at top priority.
3. Settings → Conversions API → generate an access token → `META_CAPI_TOKEN` (needs `NEXT_PUBLIC_META_PIXEL_ID` too). Redeploy.
4. Dedupe check: after a test lead, Overview → `Lead` shows connection methods **Browser and Server**, with deduplication working (same event ID). Test Events will show only the Browser leg (B1).
5. Diagnostics: no CAPI errors. Server failures are silent in code (N3).
6. Optimise the campaign for **`Lead`** only. Never `Contact` (fires on every mailto click, N7) or `LeadFormStarted`. Never create a custom conversion on URL contains `/scope-received`.
7. Retargeting audiences: use "All website visitors" (30–180 days). Avoid URL-specific audiences until the first-load-only `PageView` gap (`AdPixels.tsx:25`) is fixed. Visitors whose browser sends GPC are never in the audience, by design.

## Appendix C. Test-lead procedure (updated)

Do this after the env vars are set and a **production** redeploy is live, and before any ad spends. Run `npm test` first.

1. Use a normal browser with no ad blocker and Global Privacy Control **off**. Brave and some Firefox setups turn GPC on by default. Check in the console that `navigator.globalPrivacyControl` is not `true`.
2. Open `https://www.skoxsoftware.com/dashboards?utm_source=test&utm_medium=test&utm_campaign=tracking-check&gclid=TEST123&fbclid=TESTFB123`.
3. Have Google Tag Assistant (tagassistant.google.com) connected to that URL, the Meta Pixel Helper extension on, and Meta Events Manager → Test events open for the browser leg.
4. Before submitting, click the footer **Privacy** link, then come back to `/dashboards` (untagged). This proves the tags survive navigation.
5. Submit the form with name "TEST – ignore", a real inbox you control, and "Tracking test".
6. Check:
   - [ ] The lead email arrives at `CONTACT_EMAIL` from `LEAD_FROM_EMAIL`. Its "Source:" block shows `utm_campaign: tracking-check`, `gclid: TEST123` and `fbclid: TESTFB123`, and "pages this visit" lists `/dashboards → /privacy → /dashboards`.
   - [ ] You land on `/scope-received`.
   - [ ] GA4 → Realtime (or DebugView) shows `generate_lead`.
   - [ ] Tag Assistant shows the Google Ads `conversion` with the right `send_to` and a UUID `transaction_id`, with `user_data` set just before it.
   - [ ] Pixel Helper or Test events shows a **Browser** `Lead` with an event ID.
   - [ ] 20–60 min later: Events Manager → Overview → `Lead` shows **Browser and Server**, deduplicated. No CAPI errors under Diagnostics. (The server leg won't appear in Test events; see B1.)
   - [ ] Refreshing `/scope-received` fires **no** new `generate_lead`, Ads `conversion` or Meta `Lead`. A new `page_view`/`PageView` is expected.
7. GPC check (optional, recommended): repeat step 2 with GPC on. Pixel Helper shows no Meta pixel, and Tag Assistant shows GA4 but no AW config. Until N1 is fixed, a submit will still push the Ads conversion and `user_data` into the dataLayer; note what Tag Assistant shows.
8. Within 48 hours the Google Ads conversion action moves from "Unverified" to "Recording conversions" (or "No recent conversions", which also means the tag is seen).
9. Write the result into `docs/ads/audits/YYYY-MM-DD-tracking-test.md`.
